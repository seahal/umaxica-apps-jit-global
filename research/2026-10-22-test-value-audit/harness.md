## Retention decisions from inspected examples

- Real database restrictions and ORM restrictions are different contracts. ClientTokenKind's relation lookup, destroy refusal and raw deletion refusal stay separate.
- Broad rescue in a worker is meaningful when the main thread requires exactly one winner and an exact failure class; AuthCeremonySessionConcurrencyTest does that.
- The error-refusal taxonomy test deliberately raises a real domain exception and then asserts its code/message. That is unlike LV-001, where the test manufactures the entire Rails exception without invoking the claimed subject.
- `send` does not establish a visibility violation. OperatorToken's digest method is publicly delegated by RefreshTokenShared. Its algorithm contract needs a separate ownership decision; it was not included as a confirmed low-value test.
- The two invisible Turnstile suites import different implementations; timeout/unsupported callback behavior differs. The CSRF readers likewise exist as separate functions. Similar test bodies are not redundant while those implementations remain independent.
- Tests pinning concrete persisted constant values are not automatically boilerplate: changing such a number can reinterpret stored identity/security state.

## Review boundary

This document identifies assurance limits from inspected source and explicit repository contracts. It does not establish production deployment behavior or per-test mutation adequacy. The full static ledger marks unreviewed semantic decisions as open; it never converts absence of a heuristic signal into approval.
