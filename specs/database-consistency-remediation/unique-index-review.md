## C13 decision and compatibility

The accepted taxonomy ADR defines Vocabulary.key as table-local, shared across locales and reserved
after archival. No normal vocabulary-creation application handler depends on RecordNotUnique. The
existing duplicate DB test deliberately bypasses validation. Under the user-delegated validation
scope, normal duplicate vocabulary creation now raises RecordInvalid with a key error; validation-
disabled writes retain RecordNotUnique and immutable key updates retain the PostgreSQL restriction.
Creation-only uniqueness adds one measured key SELECT, none on unchanged existing-record validation.
No index, database, state, lifecycle, trigger, callback or physical schema changed. This does not
alter D1: normal TaxonomyTerm duplicate exceptions remain protected by their existing tests and
FIXME.
