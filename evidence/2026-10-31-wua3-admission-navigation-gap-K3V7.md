# Auth admission navigation discrepancy

- HEAD: `336811e5072a93c0523e484f905082635b28f48f`. The worktree had extensive uncommitted changes affecting this check.
- In the APP Email Step-Up integration case, an already attached and confirmed admission was presented by GET with neither `Sec-Fetch-Mode` nor `Sec-Fetch-Dest`. Temporary assertions checked those headers were absent and that the binding became redeemed; the request returned 303 and the complete probe passed (1 run, 23 assertions). The temporary assertions were removed after the observation. This was a Rails integration request in test mode, not a deployed browser or attack demonstration.
- `AuthCeremonyAdmission#render_admission_reference!` sends an attached and confirmed binding to `redeem_admission_reference_and_redirect!`, which consumes and rotates continuity. The inspected concern does not call `BrowserNavigationRequest`; the shared navigation predicate requires mode `navigate` and destination `document` or `empty`.
- The accepted `adr/sign-in-path-continuation-protocol.md` permits named GET continuation consumption only with navigation Fetch Metadata, browser binding, atomicity and the other listed conditions. `docs/security/public-entrypoints.md` also describes confirmed entry GET redemption. In contrast, both `docs/mermaid/idp-{client,operator}-auth-admission-binding.mmd` say GET checks nonce ownership without mutation. Thus the implementation, ADR's navigation condition and diagrams disagree. This probe establishes the missing-header case only; other destinations, HEAD, real browsers, affected routes and no-side-effect refusal have not been measured.
- No production behavior was changed by this investigation. The final test and its full-suite results remain as documented in `2026-10-31-wua12-app-email-handoff-P8V4.md`.
- Separately ran `test/controllers/auth/app/verifications_controller_test.rb`: 6 runs, 9 assertions, 4 failures and 1 error. Several cases expect a former POST admission/continuation form; the current route uses GET. These results do not by themselves decide whether changing the accepted navigation contract is safe. No edits were retained in that test file.
- Updated the APP and ORG admission-binding diagrams' GET note to describe the current initial relay and confirmed redemption, and to identify the unimplemented Design D navigation-metadata condition. Both verification controllers include the same inspected admission concern; the runtime probe was APP only. Scoped `git diff --check` passed. No transition was added or claimed implemented.
