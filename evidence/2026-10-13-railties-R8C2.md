`warn` record through `JitLogEvent.format` and `Rails.logger`, scrubs message/metadata before
limiting code points, records a relative first callsite and UTC timestamp, and bounds the final JSON
to 8 KiB. It omits unrelated payload fields and full backtraces. The production Sentry comment was
corrected; the existing test and development `:raise` settings were retained.

`test/subscribers/deprecation_notification_subscriber_test.rb` passed its secret-redaction, byte and
code-point boundary, UTF-8, and one-record assertions. A development runner reloaded the application
and directly instrumented one deprecation notification into a captured logger; it recorded exactly
one `rails.deprecation` line after reload. Separate development and test runner calls to
`ActiveSupport.deprecator.warn` both exited with `ActiveSupport::DeprecationException`, as required.

The production-like runner did not reach application initialization: it stopped because required
`TRUSTED_PROXIES` was absent. No value was guessed and no production database was contacted. Thus
the handler's production runtime output remains **unverified** and AT-029 is incomplete despite the
passing subscriber checks.

## REQ-045 — existing Base/Auth surfaces

Rails 8.2's `:header_or_legacy_token` deliberately accepts same-origin and same-site Fetch Metadata
without consulting a token. To honor the selected `one.md` contract while retaining Rails' Origin,
Fetch Metadata, exception and instrumentation paths, Base app/com/org application roots, Base
authority roots, and Auth app/com/org application roots now prepend a token check after Rails'
standard CSRF callbacks and before surface callbacks. They use Rails' session-bound token validator;
GET, HEAD and actual QUERY requests remain exempt. No shared cross-surface concern or Rails method
override was added. `adr/operator-capability-authorization.md` now records the matching contract.

Coverage includes same-origin valid, missing and invalid tokens on Auth admissions; same-origin
missing/invalid token refusals and valid-token success on Base preferences; same-site and missing
Fetch Metadata; cross-origin/null Origin rejection; JSON requests; refusal before preference or
admission state changes; protocol-boundary checks; and real token use in Base cookie and logout
flows. A CSRF-enabled social completion test exposed that its test session cookie was not retained
because it supplied `Host` without setting the integration session host. The test now sets the
session host; the receiver-local form token passes and cross-host/null-origin cases still refuse.
Palm and Tech entry cases remain for their later plan steps.

The focused CSRF/deprecation command group, including the exact modified Base logout cases, passed:
97 runs, 895 assertions, no failures, errors, or skips. RuboCop passed on 27 affected Ruby files;
`git diff --check` passed.
