- Created the empty scratch database `test_wu7_migration_replay_0d513551` and ran the 27 existing com setting migrations through Rails. All 27 versions matched their migration files, but the resulting schema differed from the worktree dump: ten legacy preference foreign keys were `NOT VALID` in a replay and validated in the dump. The initial runner invocation failed before database creation because a `.rake` file was required rather than loaded; the corrected invocation succeeded.

Its down direction deliberately keeps the validated constraints because PostgreSQL cannot mark them unvalidated without dropping them. On the scratch database, the number of unvalidated foreign keys went from ten to zero. On local `test_com_setting_db`, `db:migrate:up:com_setting` completed in 0.0321 seconds. No production lock duration or table scan was measured.
