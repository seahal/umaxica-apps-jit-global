## WU04 (issuer side)

- OIDC Access JWTs from the token endpoint carry `umx_contract_epoch` from `Op*ProtocolEpoch`.
- `OidcOpAccessTokenVerifier` accepts OP tokens without a `domain:` scope (realm fixed by issuer and
  cell binding); a present `domain:` scope must match the realm.

  JSON; the same Access token is refused under epoch + 1.

## WU05 (public HTTPS transport)

- `OidcOpTokenClient` (adapters) classifies success / refused / dependency / invalid_remote /
  indeterminate; no redirects followed; 429/5xx never become `invalid_grant`.
- RP Refresh (`BrowserRpAuthentication`, `CoreBrowserApiBoundary`) and callback Code exchange
  (`OidcCallback`) now call the OP over HTTPS; `OidcRpTokenClient` removed. Only `refused` clears
  cookies; other outcomes keep them.
- Test support `test/support/in_process_op_transport.rb` delivers OP token-endpoint calls to this
  app's router in-process; explicit `OutboundHttp::Connection.build` stubs still take precedence.
- Not done: reserved OP receiving capacity/listeners (needs per-role processes; containers are not
  split by user decision), UserInfo client rename, Base Self-RP reissue still in-process (OP-side).

## WU07 (building blocks, not yet wired)

- `RpCallbackCommitter`: per-sid anchor upsert+lock, revoked anchor refused, immutable identity
  binding, single live session; expired unrevoked session closed before re-enrolment.
- `RpRequestAuthenticator`: Access JWT (public JWKS) AND writer-read local session bound by
  sid/subject/issuer/epoch; disabled principal, revoked anchor/session or expiry refuse.
- Not done: callback/controllers still authenticate through the OP grant/root chain and the Global
  actor; switching them requires the domain HTTPS contracts (WU11-WU15) because RP pages use the
  Global actor for policy and data.
