## Owner decisions needed before implementation

### Matching validators

There are 59 cycle UniqueIndexChecker findings. Adding a matching Rails uniqueness validation changes a duplicate save from reaching the database unique index (normally `ActiveRecord::RecordNotUnique`) to failing model validation (`ActiveRecord::RecordInvalid`); a concurrent duplicate can still reach the database index. Six live AuthAdmissionBinding indexes are already held in `specs/database-consistency-remediation/unique-index-review.md` because `BaseAuthAdmissionCoordinator` retries `RecordNotUnique`. The `OperatorChronicle` index is an expression plus partial index and cannot be represented faithfully by a standard Rails uniqueness validation; do not add a looser validator. The other exact index/condition candidates remain listed individually in the ledger for explicit behavior review.

Three cycle LengthConstraintChecker findings are `Op{App,Com,Org}AuthorityStop.realm` on `varchar(3)`. Adding `length: { maximum: 3 }` changes the failure path for overlength values; the current database also has a realm-specific check constraint.

### Redundant authority-stop indexes

A migration would remove one ordinary index per realm while keeping its composite unique index. These are database-schema changes, so the sample below is presented for approval before editing migrations or structure dumps.

```sql
-- Before (APP; COM and ORG have the same index shapes)
CREATE INDEX index_op_app_authority_stop_participants_on_stop_id
  ON op_app_authority_stop_participants (stop_id);
CREATE UNIQUE INDEX idx_on_stop_id_grant_id_2b3b703bbe
  ON op_app_authority_stop_participants (stop_id, grant_id);

-- After
CREATE UNIQUE INDEX idx_on_stop_id_grant_id_2b3b703bbe
  ON op_app_authority_stop_participants (stop_id, grant_id);
```

Source of truth: the current APP/COM/ORG structure dumps. No stored row or index key is rewritten, and no tuple or enum changes. Compatibility: the application data/API shape is unchanged; PostgreSQL query-plan and write-cost characteristics can change, so the reversible migration and generated dumps need owner approval and later verification. The APP pair above repeats for COM/ORG with their corresponding table and index names.
