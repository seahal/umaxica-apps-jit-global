# PostgreSQL Integrity Check in the Core Service

Work was performed on 2026-09-24 against commit `2b027d5b38989d3068e4620262bfa6c6fde8df41`, with uncommitted task changes present. No shared database was written. The historical F-01–F-21 audit report was unavailable, so this is a current-state check, not a comparison with that report.

- Ruby 4.0.7, Rails 8.2.0.alpha, PostgreSQL server 17.7, and pg_dump 17.11 were observed. The `primary` PostgreSQL host and Valkey sidecar names resolved from the core container. Credentials were read locally and were not recorded.
- A read-only catalog query with finite statement and lock timeouts found 20 `development_*` and 20 `test_*` databases on `primary`. The 14 application databases with pending validation contained 203 `convalidated=false` foreign-key or CHECK constraints in total. No invalid indexes were found. The catalog query did not alter those databases.
- `/tmp/audit_constraints.rb` checked all 203 definitions against current rows in read-only transactions, with a five-second statement timeout and one-second lock timeout. It reported zero violations and zero failed checks. This does not establish the state of production or other hosts, and does not by itself authorize validation.
- A later bounded `EXISTS` check found that all 101 tables carrying those 203 definitions were empty in this development environment. The zero-violation result is therefore vacuous for populated data. The persistent checker and synthetic positive/negative probe are recorded in the subsequent Global audit evidence.
- Three uniquely named, comment-marked task-owned databases were loaded from the prechange ticket structure dumps. Rails `MigrationContext` applied the seven new migrations to each of `app_ticket`, `com_ticket`, and `org_ticket`. All three new foreign keys per database were validated. No shared `development_*` or `test_*` database received a migration.
- `/tmp/verify_ticket_constraints.rb` used only synthetic data in those three task-owned databases. It passed checks for token history, nullable sessionless tokens, actor mismatch rejection, wrong current-token ownership rejection, current-token deletion clearing its pointer, and restricted session deletion. The rejected writes had SQLSTATE `23503` and the intended constraint names.
- Structure dumps generated from the migrated task-owned databases were written to the three checked-in ticket dumps. `/tmp/verify_integrity_dumps.rb` reloaded each dump into a second task-owned database and confirmed all three new foreign keys validated and all seven migration versions present. The diff also includes PostgreSQL 17 canonical rendering of existing CHECK expressions; their meaning was not changed.
- A Rails test boot with isolated per-logical-database URL overrides was attempted only after creating task-owned databases. The application's `Umaxica::TestEnvironment::DatabaseSafety` rejected those overrides before tests ran. The normal `test_*` databases are shared, so Minitest was not run against them. No Rails test result is claimed.

The existing `NOT VALID` constraints remain unchanged in the repository pending the required persisted-shape approval. Cross-connection races and production-sized lock behavior remain unverified. The task-owned databases are disposable and contain only checked-in schema plus synthetic rows.
