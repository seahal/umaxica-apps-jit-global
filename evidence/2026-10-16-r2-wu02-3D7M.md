# R2-WU02 occupied-slot refusal evidence

Date: 2026-10-16

Revision: `17903f7d121aa33efe29f2db9235c9aa5db4b001`

The worktree contained pre-existing uncommitted application, documentation, migration and test
changes, including the R1 work and the R2-WU01 waiting-slot implementation. This evidence was
collected with those changes present.

R2-WU02 now catches the named `SessionLimitResolutionTransactionable::WaitingSlotOccupied` outcome
at `AuthenticationBase#log_in`. It returns the existing `:session_limit_conflict` result with
`http_status: :forbidden` and the generic `session_limit.login_limit_exceeded` message. The existing
flow, waiting lease, full-access tokens, cooldown state and audit state are left alone. The
infrastructure/total-row conflict path remains HTTP 503.

The parameterized model test exercises app (`N=2`), com (`N=1`) and org (`N=1`) through the real
`log_in` boundary. It verifies the existing waiting row is unchanged, no second child is created,
the refused flow remains resumable, and no token row is added.
