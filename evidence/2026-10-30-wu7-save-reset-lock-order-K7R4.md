# WU-7 concurrent save and reset lock order

- HEAD: `336811e5072a93c0523e484f905082635b28f48f`; staged, unstaged and untracked changes affected the result.
- Added a nontransactional request test for a save and a reset carrying the same JWT. An independent PostgreSQL connection holds the parent lock; the test starts the first request, observes its lock wait, then starts and observes the second before releasing the lock. It exercises both queued orders. When save is first, it updates the original active row and the stale reset creates a distinct default row. When reset is first, it retires the original and the stale save creates a distinct new row. Responses carry the expected themes and distinct subjects.
