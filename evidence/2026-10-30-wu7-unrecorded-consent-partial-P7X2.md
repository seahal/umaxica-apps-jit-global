# WU-7 partial save of unrecorded consent

- HEAD: `336811e5072a93c0523e484f905082635b28f48f`; staged, unstaged and untracked changes affected the result.
- The com settings screen submits only changed consent fields. For a preference with old affirmative flags and no consent receipt, a partial save previously created a receipt while retaining untouched old flags; the new request test reproduced the unintended affirmative value. In the same locked setting transaction, the first explicit consent choice now starts all four flags false and applies only the submitted values before creating the receipt. When a receipt already exists, a partial save preserves the other recorded choices.
- Before the change, the com receipt and initialization tests passed: 38 runs, 517 assertions. The new legacy partial-save test initially failed. The new coverage includes unbound and already-bound legacy rows and preservation of existing recorded choices. RuboCop passed on the changed concern and test.
