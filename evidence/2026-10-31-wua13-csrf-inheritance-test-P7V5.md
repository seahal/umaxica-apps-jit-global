# CSRF test-state leak affecting signup birthdate checks

- HEAD: `336811e5072a93c0523e484f905082635b28f48f`. The worktree contained extensive uncommitted changes affecting this result.
- The full suite reported signup birthdate setup errors when the CSRF meta tag was absent. The complete birthdate file passed in isolation (13 runs, 335 assertions). Reconstructed full-suite class order placed CSRF notification and Preference browser API tests before it.
- Running the Preference CSRF test followed by a birthdate test reproduced the missing-meta error (two runs, 93 assertions, one error); the corresponding CSRF notification test followed by the birthdate test reproduced it as well (two runs, eight assertions, one error). Both helpers explicitly assigned the Auth application subclass's inherited forgery-protection class attribute and then restored its value by assignment, leaving a subclass override that prevented later changes to `ActionController::Base` from propagating.
- The helpers now enable and restore the Base setting without assigning the Auth subclass. The Preference/birthdate pair passed two runs and 121 assertions; the notification/birthdate pair passed two runs and 36 assertions. The three complete test files passed 34 runs and 2,881 assertions. An intermediate attempt using a stub on the Base getter did not activate the Base API protection and was replaced before the final runs. No production code was changed.
- RuboCop and scoped `git diff --check` passed. The full suite has not been repeated after this fix; other order-dependent failures and complete WU-A13 acceptance remain unverified.
