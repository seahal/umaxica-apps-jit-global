# WU-7 com preference signing namespace

- HEAD: `336811e5072a93c0523e484f905082635b28f48f`; staged, unstaged and untracked changes affected the result.
- Added the independent `preference_com` JWT registry namespace, local keyset installation, and required com issuer/audience/revocation settings. The active kid must be configured; the com audience must equal `com`. The registry rejects public key material reused by another issuer even under a different kid. Com encoding and verification use this namespace and issuer; a supplied different namespace is refused. App/org remain on their existing shared namespace pending WU-9.
- The local keyset installer generated local com key material; no key values are recorded here and no external key distribution was performed. The non-secret com settings were added to `.env.container.devcontainer` and explicitly exported for these commands; existing shells need the updated environment. With the revocation setting removed from the process environment, `RAILS_ENV=test bin/rails runner` failed to boot with the missing-variable `KeyError`, as required.

Tests cover cross-key signature refusal for com/app/org and rejection of the same key under another issuer's kid. RuboCop passed on the seven checked Ruby files before the final active-kid check; the registry file passed again afterward.
