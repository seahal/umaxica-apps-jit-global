## Current conflicts and candidate improvements

- `config/frontend_stacks.yml` assigns Rails application shells to importmap/Propshaft and Inertia shells to Vite. README still broadly describes one Vite stylesheet per browser surface and static-only Propshaft; use the registry and current templates for implementation ownership.
- `guid/net/roots/index.html.erb` links a Vite surface stylesheet but has no explicit registry entry. Record this distribution-contract omission separately; do not change stack registration for cosmetic normalization.
- Publish ADR historical prose describes Edit as Inertia, while current publishing concerns render four shared ERB templates and registry classifies edit/org/application as Vite CSS with importmap JS. Keep the current accepted stack exception; do not recreate an Inertia migration.
- At the initial source check, `app/assets/stylesheets/application.css` contained only color-scheme, body font/margin and main minimum-height rules. Existing relay/confirmation templates and utility-heavy layouts therefore need actual computed-style examination; source alone does not establish an unstyled reachable screen.
- Legacy `sign/*` templates, shared content article templates and old preference pages must not be removed based on filename alone; dynamic dispatch/reference evidence and runtime conditions are recorded separately below.
- `base/dev` and `core/dev` root templates exist, but their root controllers declare deny_all. Human-facing file presence is not evidence of an admitted user route.
- Plain-text network roots, machine sitemap/service-worker responses and intentional relay documents remain distinct from ordinary page composition.

Shared cells are resolved from their existing owner: `auth/shared` serves surface-local Auth and existing handoff/logout callers; `shared/oidc_rp_sign_entries` serves existing Core/Warp/Palm/Edit entry controllers; `edit/org/publishing/entries` serves all four publishing families × three content audiences. These are established display abstractions, not permission to share sessions or state. Layout rows map to the corresponding family/edition application or Inertia shell; mailer layouts remain mail delivery artifacts.

## Coverage limits and follow-up

The inventory covers local source files and registered local route metadata, not user/session reachability. Controller prerequisites, hidden dynamic render names, request region, feature gates, supplied props and inherited actions may select another template. Shared ERB article views do not authorize article routes forbidden by the content boundary. The main implementation ledger must attach actual application-route browser evidence separately and record blocked authentication/database prerequisites.

No source-count percentage is presented as a defect rate. A visible issue requires a rendered state, or a narrowly stated code finding; button/checkbox target size requires actual combined hit geometry; Page.wide requires both outer-shell and content measurements; role/status grep is not a notification assessment.
