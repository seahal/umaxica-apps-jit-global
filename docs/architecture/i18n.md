# I18n

User-facing application copy must live in locale files, not inline fallbacks.

Do not use `I18n.t(..., default: "...")`, `t(..., default: "...")`, or equivalent inline fallback
copy in controllers, services, views, policies, jobs, or helpers.

Do not build translation keys dynamically at runtime, including interpolation such as
`t("abc.#{value}")`, concatenation, or other patterns where the final key is not explicit in source.

## Locale bundles are a closed set

All translations live in exactly four bundles, one per region and language:

- `config/locales/jp/en.yml`
- `config/locales/jp/ja.yml`
- `config/locales/us/en.yml`
- `config/locales/us/ja.yml`

Do not create another file under `config/locales/`, including a per-feature or per-namespace bundle
such as `jp/some_feature.ja.yml`. Add the keys to the four existing bundles, under the same key path
in each, in alphabetical order.

`config/initializers/locale.rb` enforces this at boot: any extra or missing bundle raises with the
list of offending files, so every Rails command fails until the set is restored. The check lives in
the initializer rather than only in this document because an earlier, undocumented form of the
constraint was removed without anyone noticing; the comment in that file records the history.

Adding a region or a language is the one legitimate reason to change the set. Extend
`expected_locale_bundles` in the initializer in the same change that adds the file.

## Adding a message

When adding a message:

1. Add an explicit translation key under `config/locales/`.
2. Add the key to each of the four bundles listed above.
3. Keep surface-specific text under the matching `sign.app`, `sign.com`, or `sign.org` namespace
   unless an existing shared namespace is already the correct abstraction.
4. Call the key directly from code.

Example:

```ruby
redirect_to("/", notice: t("sign.app.registration.cancelled_retry_later"))
```

Avoid:

```ruby
redirect_to(
  "/",
  notice: t(
    "sign.app.registration.cancelled_retry_later",
    default: "Registration cancelled. Please wait a while before registering again.",
  ),
)
```

Inline defaults hide missing keys, weaken locale coverage, and make copy review harder across the
`app`, `org`, and `com` surfaces.

Dynamic keys hide which translation is actually used until execution time, which makes review and
static checking unreliable.

See `adr/i18n-explicit-translation-keys.md`.
